# 지하철 수요 데이터

지하철 승하차 자료를 역별로 모아 하루 평균 승하차 인원과 시간대 지표를 만들고, 역 좌표를 행정동 경계에 연결합니다. 결과는 서울 역 306개입니다.

## 데이터

| 데이터 | 제공 | 기간 |
|---|---|---|
| 일별 역별 승하차 (`OA-12914`, 월별 CSV) | 서울 열린데이터광장 | 2024-09-01 ~ 2026-09-30 |
| 월별 역별 시간대 승하차 (`OA-12252`, Open API `CardSubwayTime`) | 서울 열린데이터광장 | 2024-09 ~ 2026-09 |
| 역 좌표 (`data/서울시 역사마스터 정보.json`) | 서울시 | |
| 행정동 경계 (`data/HangJeongDong_ver20260701.geojson`) | github.com/vuski/admdongkor | 2026-07-01 행정구역 |
| 행정동 기준표 (`competition/dong_area.csv`) | 경쟁 축 (팀 공통) | 427개 |

기간 끝이 팀 공통 기준일(2026-09-30, `docs/common-rules.md`)과 같습니다.

## 실행

```bash
pip install -r demand/requirements.txt
cd demand
python subway.py --cache <원본 저장 폴더>   # 원본을 받아 역별 지표 계산 (--cache 는 선택, 다시 돌릴 때 원본을 재사용)
python map_stations_to_dongs.py            # 역 → 행정동 연결, 서울 역만 남김
```

두 번째 스크립트는 수요 파일을 서울 역만 남긴 채로 덮어씁니다. 수동 매핑만 고쳤을 때도 `subway.py`부터 다시 돌려야 매핑 기록에 서울 밖 역까지 남습니다(`--cache`를 주면 원본을 다시 받지 않음).

인증키는 다른 축과 같이 저장소 맨 위 `.env`의 `SEOUL_API_KEY`를 씁니다(git에 올라가지 않음).

## 처리 규칙

- **같은 역 이름 합치기**: 이름이 바뀌었거나 노선마다 이름이 다른 같은 역은 이름 하나로 합칩니다(`subway.py`의 `STATION_ALIASES`). 역사마스터 좌표가 같은 위치인 것을 확인했습니다.

  | 합친 이름 | 원래 이름 | 이유 |
  |---|---|---|
  | 불암산 | 당고개 | 2025-04 이름 변경 |
  | 삼각지(전쟁기념관) | 삼각지 | 2025-04 이름 변경 (4·6호선) |
  | 숙대입구(서울시교육청) | 숙대입구(갈월) | 2026-07 이름 변경 |
  | 총신대입구(이수) | 이수 | 4호선과 7호선에서 이름이 다른 환승역 |

- **같은 이름인 다른 역 나누기**: 노선으로 나눕니다(`LINE_SPECIFIC_NAMES`). 경의선 신촌 → `신촌(경의중앙선)`(2호선 신촌과 714m 떨어진 다른 역), 중앙선 양평 → `양평(중앙선)`(경기 양평군, 5호선 양평과 다른 역).
- **환승역**: 이름이 같은 노선끼리는 날짜별로 더해 한 역으로 셉니다.
- **중복 행**: 시간대 API가 2026-03, 2026-07에 같은 행을 두 번씩 돌려줬습니다. 같은 달·노선·역(일별은 같은 날·노선·역)이 두 번 오면 하나만 남깁니다.
- **주말**: 토·일만 주말로 봅니다. 공휴일은 평일로 셉니다.
- **서울 밖 역**: 최종 수요 파일에서 뺍니다. 매핑 기록(`station_dong_mapping.csv`)에는 남깁니다.

## 결과 파일

`subway_demand_202409_202609.csv` (서울 역 한 줄, 306행). 인원은 모두 **하루 평균, 명**입니다. 승하차는 승차와 하차를 더한 값이라 한 사람이 타고 내리면 두 번 셉니다(유동인구가 아님).

| 컬럼 | 뜻 |
|---|---|
| `SUB_STA_NM` | 역 이름 (키) |
| `adm_cd`, `adm_cd8`, `stat_cd`, `adm_nm`, `gu` | 역이 있는 행정동 (`competition/dong_area.csv`와 같은 값) |
| `평일_일평균_승하차` | 평일(월~금) 하루 평균 승차+하차 인원 |
| `주말_일평균_승하차` | 주말(토·일) 하루 평균 승차+하차 인원 |
| `주간_일평균_승하차` | 일주일 기준 하루 평균 = (평일 × 5 + 주말 × 2) ÷ 7. 정렬 기준 |
| `주말_평일_비율` | 주말 ÷ 평일. 1보다 크면 주말에 더 붐빔 |
| `아침_수요지수(출근하차)` | 07~09시 하차 인원 (하루 평균) |
| `아침_승차인원` | 07~09시 승차 인원 (하루 평균) |
| `오피스_밀집도` | 아침 하차 ÷ 아침 승차. 1보다 크면 아침에 들어오는 사람이 많은 업무지구 |
| `저녁_집객지수(유입)` | 18~20시 하차 인원 (하루 평균) |
| `심야_귀가지수(유흥/회식)` | 22~23시 승차 인원 (하루 평균) |

시간대 지표는 월별 합계를 그 달의 일수로 나눈 뒤 25개월을 평균한 값입니다.

`station_dong_mapping.csv` (역 한 줄, 서울 밖 포함 533행): 매칭한 역사마스터 이름, 좌표, `mapping_status`(`mapped`·`manual_override`·`outside_seoul`), 수동 매핑 사유.

## 수동 매핑

역도 가게와 같이 **좌표 기준**으로 행정동을 붙입니다. 경계도 가게와 같습니다: `data/HangJeongDong_ver20260701.geojson`은 공개 원본(vuski/admdongkor)과 해시가 같고, 이 경계로 공용 파일 가게 638,138곳의 좌표를 다시 붙이면 경쟁 축이 붙인 행정동과 모두 같습니다(2026-10-17 확인). 환승역처럼 노선별 좌표가 서로 다른 동에 떨어지면 `station_dong_overrides.csv`에서 **그 후보 중 하나**를 고릅니다(27개). `adm_cd`는 기준표에 있는 행안부 10자리 코드여야 하고 `reason`은 필수입니다. 후보 밖의 동은 고르지 않습니다.

역 건물의 공식 주소(도로명주소 검색API)와 대조하면 212개 역이 같은 동이고, 59개 역은 역이 동 경계 위에 있거나 노선별 건물이 다른 동에 있어 좌표 기준 동과 주소의 동이 다릅니다(예: 신사역은 좌표상 신사동, 주소상 논현1동). 35개 역은 주소에서 역 건물을 찾지 못했습니다(2026-10-17 확인).

## 한계

- 수요는 지하철역이 있는 행정동만 알 수 있습니다. 역이 없는 동네는 비어 있습니다.
- 버스 승하차와 생활인구는 쓰지 않습니다.
