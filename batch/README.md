# 월간 데이터 갱신 (배치)

매월 1일 09:00(한국 시간)에 공공데이터를 다시 받아 네 축을 **지난달 말일 기준**으로 다시 계산하고, 검증을 통과하면 서비스 DB를 한 번에 바꿉니다. 실패하면 7일까지 매일 09:00에 다시 시도합니다. 화면 위쪽에는 지금 데이터의 기준일이 보이고, 물음표에 올리면 "매월 자동으로 갱신"된다고 알려 줍니다.

## 순서

| 단계 | 하는 일 | 실패하면 |
|---|---|---|
| fetch | 서울 Open API에서 인허가 3종(`LOCALDATA_072404·072405·072218`)을 받아 CSV로 저장 (`fetch_permits.py`) | 멈춤. DB 그대로 |
| prepare | 공용 파일·행정동 기준표·경쟁 지표 (`competition/permits_prep.py`) | 멈춤. DB 그대로 |
| axes | 안정성(`stability/build_stability.py`), 자리(`jari/sites.py`), 수요(`demand/subway.py`, `map_stations_to_dongs.py`, 지하철 원본이 올라온 가장 최근 달까지 25개월. 1일에는 지난달 자료가 아직 없을 수 있어 한 달 앞 달까지 씀), 데이터 분석 페이지 숫자 | 멈춤. DB 그대로 |
| validate | 파일·컬럼·행 수·행정동 코드, 기준일, 안정성과 경쟁 축의 행정동별 영업 중 가게 수가 같은지 | 멈춤. DB 그대로 |
| load | 임시 표에 넣고, 행정동·업종 표가 지금과 같은지와 행 수가 갑자기 줄지 않았는지(90% 미만이면 중단) 검사한 뒤, **한 트랜잭션**으로 기존 행을 지우고 새 행을 넣음 (`backend/batch_load.py`) | 롤백. DB 그대로 |

- **기존 데이터를 지키는 방법**: load 전에 멈추면 DB를 건드리지 않습니다. load 안에서 실패하면 트랜잭션 전체가 롤백됩니다. 커밋 전까지 API는 기존 데이터를 계속 읽어서 갱신 중에도 서비스가 멈추지 않습니다.
- **실패하면 다시 시도**: 예약은 매월 1~7일 매일 09:00입니다. 이번 기준일로 이미 성공했으면 바로 끝나므로, 1일에 성공하면 나머지 날은 아무것도 하지 않고, 실패하면 다음 날 다시 돕니다. 7일까지 모두 실패하면 사람이 원인을 보고 손으로 돌립니다.
- **중복 실행 방지**: GitHub Actions `concurrency`와 PostgreSQL advisory lock을 같이 씁니다. 이미 다른 배치가 돌고 있으면 이번 실행은 `skipped`로 기록하고 끝납니다. FastAPI 서버가 여러 대여도 배치는 서버 밖에서 하나만 돕니다. 계산하는 동안 잠금 연결이 끊겼으면 교체 직전에 다시 잠급니다.
- **기록**: `batch_run` 표에 실행마다 시작·끝 시각, 결과(running·success·failed·skipped), 마지막 단계, 실패 이유, 표별 행 수를 남깁니다. 시간 초과·취소로 running 인 채 남은 기록은 다음 배치가 failed 로 바꿉니다. `GET /api/data/pipeline`과 화면이 이 기록을 보여 줍니다.
- 성공하면 데이터 분석 페이지 숫자(`frontend-html/analysis/data.js`)를 커밋해 Vercel이 다시 배포합니다.

## 왜 FastAPI 안 스케줄러가 아니라 GitHub Actions인가

Render 무료 서버는 요청이 없으면 잠들어 예약 시각에 깨어 있지 않을 수 있고, 인허가 70만 건 계산은 무료 서버 메모리로 버거우며, 서버 디스크는 다시 배포하면 지워집니다. GitHub Actions는 공개 저장소에서 무료이고, 서버와 따로 돌아 계산 중에도 API가 느려지지 않습니다.

## 켜기·끄기

1. 저장소 **Settings → Secrets and variables → Actions → Secrets**에 `SEOUL_API_KEY`, `DATABASE_URL`(Render 환경변수와 같은 값)을 넣습니다. 없으면 배치가 실패로 끝나고 DB는 그대로입니다.
2. 잠시 멈추려면 **Variables**에 `BATCH_DISABLED` = `true`.
3. 손으로 돌리기: **Actions → 월간 데이터 갱신 → Run workflow**. 기준일을 비우면 지난달 말일, `load`를 끄면 계산·검증만 합니다. 손으로 돌리면 이미 성공한 기준일도 다시 계산합니다.

로컬에서:

```bash
python batch/run.py --no-load                    # 계산·검증만
python batch/run.py --trigger manual             # DATABASE_URL 이 있으면 DB까지 교체
```
