# 공통 데이터 규칙

모든 축이 같은 가게를 같은 방법으로 세기 위한 규칙입니다.

이 규칙을 정하기 전(2026-10-16)에는 축마다 규칙을 따로 정해서, 같은 동네·같은 업종인데도 축마다 "영업 중인 가게 수"가 다르게 나왔습니다. 화면에 나란히 띄우면 숫자가 서로 안 맞았습니다. 지금은 인허가 데이터를 쓰는 경쟁·안정성·자리 축이 이 규칙으로 다시 계산했습니다(#8, #9, #10).

**규칙을 넣는 곳**: 가게마다 표시가 필요한 규칙(4 폐업일 없음, 5 팝업)은 공용 파일 `permits_base.csv`를 만드는 코드(`competition/permits_prep.py`) 한 곳에서 열로 붙입니다. 각 축은 그 열을 보고 거르기만 하고, 같은 판정을 축마다 다시 만들지 않습니다. 나머지 규칙(기준일, 업종, 구 평균 등)은 각 축이 계산할 때 지킵니다.

## 규칙을 정하기 전 축마다 달랐던 점 (2026-10-16)

| | 경쟁 | 자리 | 안정성 |
|---|---|---|---|
| 쓰는 데이터 | 공용 파일 | 공용 파일 | 따로 수집 (10/15) |
| 행정동 붙이기 | 좌표만 (경쟁 축 PR 머지되면 주소로 보충) | 좌표 + 주소 | 좌표만 (가게 9.4% 빠짐) |
| 폐업했는데 폐업일이 빈 가게 | 영향 없음 | 뺌 | 일부 계산에만 뺌 |
| 백화점·행사 팝업 | 안 거름 | 안 거름 | 뺌 |
| 주인만 바뀐 가게 | 해당 없음 | 한 가게로 합침 | 따로 셈 |
| 업종 | 카페·제과점·한식 3개 | 3개 | 12개 |
| 기준일 | 데이터 받은 날 상태 | 10/12 (PR #6에서 9/30으로) | 10/15 |

예를 들어 자리 축에서 "10년간 가장 많이 바뀐 자리" 상위 10곳은 전부 백화점·복합몰·호텔이 든 대형 건물입니다(삼성동 159 코엑스, 반포동 19-3 센트럴시티 등). 안정성 축은 같은 곳을 팝업으로 보고 뺐습니다.

## 규칙

### 1. 데이터는 공용 파일 하나로 고정
- 모든 축이 `permits_base.csv`를 씁니다. 따로 수집하지 않습니다.
- **발표까지 원본을 다시 받지 않습니다.** 지금 공용 파일의 원본(경쟁 축이 2026-10-13에 서울열린데이터광장에서 내려받은 CSV)을 그대로 씁니다. 공용 파일을 다시 만들 때도 원본은 그대로 둡니다.
- 행정동은 `adm_cd`(10자리)로 맞춥니다. 좌표가 없으면 주소로 채웁니다(`jari/dong_fill.csv`, 경쟁 축 PR에서 반영).

### 2. 기준일은 2026-09-30
- "최근 1년 폐업" 같은 숫자를 셀 때 오늘을 2026-09-30으로 봅니다.
- 이유
  - 수요 축 지하철 데이터가 2026년 9월에서 끝납니다. 모든 축을 "2026년 9월 말 기준"으로 설명할 수 있습니다.
  - 공용 파일의 10월 데이터는 9일치뿐입니다(10/09 인허가, 10/10 폐업까지). 덜 찬 달을 섞지 않습니다.
  - 지표가 1년·3년·10년 단위라 열흘을 빼도 숫자가 거의 바뀌지 않습니다.
- 9/30 뒤에 난 인허가는 뺍니다. 9/30 뒤에 폐업한 가게는 **9/30에는 영업 중**이었던 가게로 셉니다(빼지 않습니다).
- "지금 영업 중"도 데이터 받은 날의 상태가 아니라 9/30에 영업 중이던 가게로 셉니다. 경쟁 축 밀도도 마찬가지입니다.
- 팝업 건물 판정(규칙 5)의 "최근 3년"도 9/30부터 거꾸로 셉니다.

### 3. 업종은 카페·제과점·한식 3개
- 모든 축이 공용 파일의 `category` 열을 그대로 씁니다.
- 안정성 축의 12개 분류는 쓰지 않습니다. 예를 들어 안정성 축의 "베이커리·디저트"에는 아이스크림 가게가 들어가서 경쟁 축의 "제과점"과 범위가 다릅니다.

### 4. 폐업했는데 폐업일이 빈 가게 → `close_date_missing` 열
- 언제 닫았는지 모르는 가게입니다(31곳, 1981~2002년 허가).
- 날짜가 필요한 계산(신규, 폐업, 생존율, 영업 기간, 자리 회전)에서는 **모두** 뺍니다. 일부 계산에만 빼면 비율의 위아래가 서로 다른 가게 묶음이 됩니다.
- 공용 파일에서 지우지는 않고 표시만 합니다.

### 5. 팝업·행사 매장 → `is_temp` 열
- 아래 둘 중 하나에 해당하고 **90일 안에 폐업**했으면 팝업으로 봅니다.
  - 상호에 "한시적·임시·팝업·행사"가 들어감
  - 팝업이 몰리는 건물: 최근 3년 인허가가 30건 이상이고 그중 절반 이상이 90일 안에 폐업한 지번
- 상호만 맞고 오래 영업한 가게(예: "대행사식당")는 일반 가게입니다.
- 모든 축이 뺍니다. 판정 방법은 안정성 축(PR #4)을 따릅니다.

### 6. 주인만 바뀐 가게 합치기 (자리 축만, 공용 파일에는 안 넣음)
- 같은 지번, 같은 상호로 **이전 가게 폐업 30일 전 ~ 폐업 후 90일 안**에 새 인허가가 나면 같은 가게로 봅니다. 주인이 바뀌면 인허가 번호가 새로 나오기 때문입니다.
- **자리 축만 씁니다.** 자리 축은 "자리가 몇 번 바뀌었나"를 보므로 주인만 바뀐 건 바뀐 게 아닙니다.
- **안정성 축 생존율에는 쓰지 않습니다.** 쓰면 전 주인이 접고 나간 경우도 "버텼다"로 세집니다. 지금 생존율(한식 61.2%, 카페 62.7%, 제과점 60.2%)도 통계청 「2015년 기업생멸행정통계」의 숙박·음식점업 3년 생존율(30.3%, 언론 보도로 확인. 더 최근 연도의 3년 생존율은 찾지 못함)보다 높습니다. 통계청은 사업자 단위, 우리는 인허가 단위라 정의가 다릅니다.
- 자리 축만 쓰므로 공용 파일에 열로 넣지 않고 `jari/sites.py` 안에서 계산합니다. 기준을 정한 근거는 `jari/README.md`에 있습니다.

### 7. 동네 가게 수가 적으면 구 평균
- 한 동네·한 업종에서 **각 지표를 계산할 때 쓰는 가게 수가 20곳 미만**이면 그 구의 평균을 보여 주고, 화면에 "구 평균"이라고 표시합니다. 가게 5곳 중 1곳만 망해도 폐업률이 20%로 튀기 때문입니다.
  - 예: 교체율·신규율은 1년 전에 영업 중이던 가게 수, 3년 생존율은 3~8년 전에 연 가게 수가 기준입니다(PR #4의 정의).
- 표시는 지표마다 따로 합니다. 교체율은 동네 값인데 생존율만 구 평균일 수 있습니다.

### 8. 지번 표기 맞추기
- "106-0"은 "106"과 같은 지번, "256-0257"은 "256-257"입니다. 번지가 0인 주소("0-0")는 지번으로 묶지 않습니다.
- 표기만 맞추고, 비슷한 주소를 같은 곳으로 추측하지는 않습니다(루트 README "주소 정규화 방침" 유지).
- `jari/common.py`의 `jibun_key()`를 씁니다. 규칙 5의 팝업 건물 판정과 규칙 6의 가게 합치기도 이 함수를 씁니다.
