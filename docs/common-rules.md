# 공통 데이터 규칙 (초안)

모든 축이 같은 업소를 같은 방식으로 세도록 정한 규칙입니다. 지금은 축마다 규칙을 따로 정해서, 같은 동·같은 업종인데도 축마다 "영업 중 업소 수"가 다르게 나옵니다.

- 초안입니다. 이 PR 댓글로 의견 주시고, 합의되면 머지합니다.
- 규칙은 공용 파일 `permits_base.csv`를 만드는 단계(`competition/permits_prep.py`)에 넣습니다. 각 축은 이 파일을 읽고 **열로 거르기만** 합니다. 축 코드에 같은 규칙을 다시 만들지 않습니다.

## 왜 필요한가

| 규칙 | 경쟁 | 자리 | 안정성 |
|---|---|---|---|
| 입력 데이터 | `permits_base.csv` | `permits_base.csv` | 서울 API에서 따로 수집 |
| 행정동 | 좌표 + 주소(`dong_fill`, PR #3) | 좌표 + 주소 | 좌표만 (업소 9.4% 빠짐) |
| 폐업했는데 폐업일 없음 | 영업 중이 아니라 자연히 빠짐 | 뺌 | 시점 지표에서만 뺌, 신규에는 들어감 |
| 백화점·행사 팝업 | 안 거름 | 안 거름 | 뺌 |
| 주인 바뀌어 다시 낸 인허가 | 해당 없음 | 한 가게로 합침 | 안 합침 |

이대로 화면에 나란히 띄우면 숫자가 서로 안 맞습니다. 예를 들어 자리 축의 "10년간 가장 많이 바뀐 자리" 상위 10곳은 전부 백화점·복합몰입니다(삼성동 159, 반포동 19-3 등). 안정성 축은 같은 곳을 팝업으로 보고 뺐습니다.

## 규칙

### 1. 입력은 `permits_base.csv` 하나
- 모든 축이 이 파일을 씁니다. 따로 수집한 원본으로 지표를 만들지 않습니다.
- 행정동은 `adm_cd`(10자리)로 맞추고, 찾은 방법은 `dong_via`(coord / jibun / road)에 둡니다. 좌표가 없으면 주소로 채웁니다(PR #3).

### 2. 기준일 하나
- 모든 축이 같은 기준일을 씁니다. 제안: **2026-10-15**
- 기준일 뒤에 난 인허가·폐업은 어떤 판정에도 쓰지 않습니다.

### 3. 폐업했는데 폐업일 없는 업소 → `close_date_missing` 열
- 언제 닫았는지 모르므로 **시점이 들어간 지표(신규, 폐업, 생존율, 영업 기간, 회전)에서 모두 뺍니다.** 분자와 분모 양쪽에서 같이 뺍니다.
- 공용 파일에서는 지우지 않고 열로 표시만 합니다.

### 4. 팝업·임시 영업 → `is_temp` 열
- 아래 둘 중 하나이고, **90일 안에 폐업**했으면 임시 영업입니다.
  - 상호에 "한시적·임시·팝업·행사"가 들어감
  - 다발 건물: 최근 3년 인허가 30건 이상이고 그중 절반 이상이 90일 안에 폐업한 지번
- 이름만 맞고 오래 영업한 가게(예: "대행사식당")는 정상 업소입니다.
- 모든 축이 기본으로 뺍니다. 기준은 안정성 축(PR #4) 규칙을 따릅니다.

### 5. 같은 가게 합치기 → `store_id` 열
- 같은 지번, 같은 상호로 **이전 가게 폐업 30일 전 ~ 폐업 후 90일 안**에 새 인허가가 나면 한 가게로 봅니다. 주인 변경이나 업종 전환 때 관리번호가 새로 나오기 때문입니다.
- 가게 수, 생존율, 회전은 `store_id` 기준으로 셉니다. 기준을 정한 근거는 `jari/README.md`에 있습니다.

### 6. 지번 표기 하나
- "106-0"은 "106"과 같은 지번, "256-0257"은 "256-257"입니다. 번지가 0인 주소("0-0")는 지번으로 묶지 않습니다.
- `jari/common.py`의 `jibun_key()`를 씁니다. 다발 건물 판정(규칙 4)과 가게 합치기(규칙 5)도 이 키를 씁니다.
